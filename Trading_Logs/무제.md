현재 토스증권 단타 자동매매 봇(Chrome Extension)을 '개인화된 로컬 AI 퀀트 에이전트'로 고도화하는 작업을 진행 중이야. 
시장의 기술적 지표(MA, RSI)와 수급 데이터를 분석하는 프론트엔드(`background.js`)와, 내 개인 투자 위키(`D:\주식정보\주식투자\wiki`)를 의미 기반(Semantic)으로 검색하는 **Python LangChain RAG 백엔드 서버**를 결합하려고 해.

아래 지시사항에 따라 Python 서버 코드와 `background.js`의 업데이트 코드를 완벽하게 작성해 줘.

### [Part 1: Python LangChain RAG 서버 구축 (`rag_server.py`)]
로컬 파일에 접근하기 위해 FastAPI와 LangChain을 활용한 독립된 백엔드 서버를 만들어 줘.
- **기술 스택:** FastAPI, Uvicorn, LangChain, ChromaDB
- **임베딩 및 LLM:** 로컬 Ollama 사용 (`nomic-embed-text` 또는 `qwen2.5` 활용)
- **로직 구현:**
  1. 서버 기동 시 `D:\주식정보\주식투자\wiki` 경로의 모든 `.md` 파일을 `DirectoryLoader`로 읽어와.
  2. `RecursiveCharacterTextSplitter`로 문서를 적절히 청킹(Chunking)하고, Chroma 벡터 DB에 저장(임베딩)하는 `init_vector_db` 함수를 작성해.
  3. **API 엔드포인트:** `POST /api/rag/search`
     - Request body: `{ "query": "검색할 상황 문장", "top_k": 3 }`
     - Response: 벡터 스토어에서 유사도가 가장 높은 상위 3개 문서 청크를 결합하여 `{ "context": "결합된 텍스트" }` 형태로 반환.
- 서버 실행에 필요한 `requirements.txt` 내용도 함께 주석이나 별도 파일로 제공해 줘.

### [Part 2: background.js 워크플로우 통합 및 API 연동]
기존의 단순 신호 발생 로직을 AI 에이전트 워크플로우로 전면 개편해 줘.

**1. RAG 검색 함수 구현 (`searchWikiKnowledge`)**
- 매수/매도 예비 신호가 발생했을 때 호출됨.
- `fetch`를 사용해 `http://127.0.0.1:8000/api/rag/search`를 찔러.
- 검색 쿼리(`query`)는 지능적으로 조립해: *"종목명은 ${ticker}이고, ${reason}(예: RSI 30 이하 과매도) 상태야. 나의 투자 원칙 위키에서 이와 유사한 상황의 주의점, 손절폭, 자금 투입 비중 원칙을 찾아줘."*

**2. 에이전트 판단 함수 구현 (`decideTradeWithQwen`)**
- 시장 데이터(`signalDetail`), 수급 데이터(`state.supplyData`), RAG 서버에서 받아온 위키 컨텍스트, 그리고 가상의 현재 가용 예수금("$10,000")을 텍스트 프롬프트로 조립해.
- Ollama API(`qwen2.5:14b`)를 호출하여 최종 판단을 요청해. (temperature: 0.1)

**3. 워크플로우 파이프라인 적용 (`evaluateSignal`)**
- 조건 달성(예: 골든크로스+수급강세) -> `searchWikiKnowledge` (과거 원칙 조회) -> `decideTradeWithQwen` (AI 판단) -> 결과 기반 디스코드 알림 발송 및 옵시디언 로깅.
- AI가 `decision: "PASS"`를 내리면 매수하지 않고 사유만 로그로 남기도록 분기 처리해.

### [Part 3: Qwen2.5 시스템 프롬프트 및 JSON 파싱]
AI가 반드시 규칙을 지키고 기계가 읽을 수 있는 형태로 응답하도록 강제해 줘.

**1. 시스템 프롬프트 (`OLLAMA_TRADER_SYSTEM_PROMPT`)**
```text
너는 나의 '개인 투자 원칙 위키'를 완벽하게 학습한 AI 퀀트 트레이더야. 
[시장 지표]와 [수급 상황]도 중요하지만, 내가 제공한 [나의 투자 원칙 및 과거 기록]에 적힌 룰(최대 비중, 손절 라인, 금지 패턴 등)을 최우선으로 절대 준수해야 해.
현재 가용 자본을 바탕으로 아래 JSON 형식으로만 응답해. 마크다운 코드 블록 외에 다른 설명은 절대 추가하지 마.

{
  "decision": "BUY" | "PASS" | "SELL",
  "allocation_percent": 0.0, // 내 전체 자본 중 몇 %를 투입할지 (예: 0.15 = 15%)
  "expected_return_rate": 0.0, // 기대 수익률 (%)
  "target_price": 0.0, // 목표 익절가
  "stop_loss": 0.0, // 손절가
  "reason": "위키 원칙에 근거한 결정 논리 1줄"
}
````

**2. 안전 파싱 (Safe Parsing)**

- AI 응답에서 정규식(`match(/\{[\s\S]*?\}/)`)을 사용해 JSON 텍스트만 추출한 뒤 `JSON.parse`를 수행해.
    
- 파싱 에러나 API 타임아웃 발생 시, 시스템 보호를 위해 무조건 `{ decision: "PASS", reason: "AI 오류로 인한 시스템 강제 관망" }`을 반환하는 예외 처리를 확실하게 해 줘.
    

**3. 디스코드 알림 수정**

- "BUY" 결정 시, 디스코드 Embed 필드에 `비중(%)`, `목표가`, `손절가`, `기대 수익률`, `AI 판단 근거(reason)`를 예쁘게 추가해서 알림이 오도록 `sendDiscordAlert` 함수를 업데이트해 줘.
