# 2026-05-10 — yfinance 펀더멘털 연동

## 개요

`runAgentPipeline`에서 AI에게 전달되던 5개 null 변수(vix, peg_ratio, roc_percentile, earnings_yield_percentile, magic_formula_rank)를 yfinance 실제 데이터로 채웠다.

---

## 구현 내용

### rag_server.py — 신규 엔드포인트

#### `GET /api/fundamentals?ticker=NVDA`

yfinance로 종목 재무 데이터를 조회하고 휴리스틱 백분위를 계산해 반환.

**반환 필드:**

| 필드 | 출처 | 설명 |
|------|------|------|
| `peg_ratio` | yfinance `pegRatio` | 피터 린치 저평가 기준 |
| `roe` | yfinance `returnOnEquity` | 소수 단위 (0.20 = 20%) |
| `forward_pe` | yfinance `forwardPE` | 선행 P/E |
| `vix` | yfinance `^VIX` | 공포지수 |
| `roc_percentile` | 휴리스틱 (ROE 기반) | 0~100, 높을수록 ROC 우량 |
| `earnings_yield_percentile` | 휴리스틱 (ForwardPE 기반) | 0~100, 높을수록 저평가 |
| `magic_formula_rank` | (ROC+EY)/2 → 1~100 변환 | 낮을수록 마법공식 우량 |
| `source` | - | `yfinance` / `isin_skipped` / `rate_limited` |

**ISIN 코드 처리**: `NAS0240905004` 같은 토스 내부 코드는 yfinance 스킵, VIX만 반환.

#### `GET /api/vix`

VIX 공포지수 단독 조회 (5분 캐시). background.js 전역 갱신 알람용.

### 휴리스틱 백분위 기준 (마법공식 기준)

**ROC 백분위 (ROE 기반)**:

| ROE | 백분위 |
|-----|--------|
| ≥ 40% | 95 |
| ≥ 30% | 90 |
| ≥ 20% | 80 ← 마법공식 우량 기준선 |
| ≥ 15% | 70 |
| ≥ 10% | 55 |
| ≥ 5% | 40 |
| < 5% | 20 |

**이익수익률 백분위 (ForwardPE 기반)**:

| ForwardPE | 백분위 |
|-----------|--------|
| < 10 | 95 |
| < 15 | 85 |
| < 20 | 70 ← S&P500 평균 수준 |
| < 25 | 55 |
| < 35 | 40 |
| ≥ 35 | 20 |

**마법공식 순위**: `rank = 100 - (ROC백분위 + EY백분위) / 2` → 1~100 클램핑

### background.js — 변경 사항

| 항목 | 내용 |
|------|------|
| `_globalVix` | VIX 전역 변수 (10분 알람으로 갱신) |
| `fetchAndUpdateVix()` | `/api/vix` 호출 → `_globalVix` 갱신 |
| `fetchFundamentals(ticker)` | `/api/fundamentals` 호출 → StockState 4개 필드 저장 |
| `FUNDAMENTALS_CACHE_MS` | 4시간 (Yahoo Finance 레이트 리밋 방지) |
| `runAgentPipeline` | RAG 검색 + 펀더멘털 조회 병렬 실행 |
| StockState 신규 필드 | `peg_ratio`, `roc_percentile`, `earnings_yield_percentile`, `magic_formula_rank`, `fundamentalsUpdatedAt` |
| `tossVixPoll` 알람 | 10분 주기 VIX 갱신 |

## 실제 계산 예시 (AAPL 기준)

```
ROE = 141.5%  → roc_percentile = 95 (최우량)
ForwardPE = 30.7  → ey_percentile = 40 (다소 고평가)
magic_formula_rank = 100 - (95+40)/2 = 32 (매수 후보 경계)
peg_ratio = 2.57 (>2.0 = 고평가 경계)
```

## 기술적 이슈 및 해결

### Yahoo Finance 레이트 리밋

- 원인: 테스트 중 단시간 반복 호출로 IP 차단
- 해결: 15분 쿨다운 변수 `_rate_limited_until` 추가 (서버 메모리)
- 캐시 TTL을 30분 → 4시간으로 연장해 실사용 중 호출 빈도 최소화
- 실사용에서는 하루 수 회 이내 호출이므로 차단 발생 안 함

### SSL 인증서 문제 (yfinance 1.3.0)

- 원인: yfinance 1.3.0이 curl_cffi 사용, Windows 시스템 CA store 미인식
- 해결: yfinance 0.2.55로 다운그레이드 (requests 기반)
- `requests.Session(verify=False)` + `urllib3.disable_warnings()` 적용

### CP949 인코딩 오류

- 원인: Windows 터미널에서 em 대시(—) 문자 출력 불가
- 해결: em 대시를 ASCII 하이픈(-)으로 교체
