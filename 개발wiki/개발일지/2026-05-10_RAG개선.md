# 2026-05-10 — RAG 서버 감사 및 개선

## 개요

RAG 서버의 검색 품질을 감사하고 두 가지 문제를 발견·수정했다: (1) `log.md`가 검색 결과를 오염시키는 문제, (2) 핵심 원칙 파일의 검색 우선순위가 낮은 문제.

---

## 감사 수행

3개 쿼리로 검색 품질 테스트:
1. "골든크로스 발생 시 매수 비중은?" → 핵심 원칙 파일 반환 여부 확인
2. "RSI 과매도 단기 반등 전략" → 기술적 분석 파일 반환 여부 확인
3. "손절폭 5% 적용 원칙" → **log.md가 1위로 반환됨 (문제 발견)**

---

## 문제 1: log.md 검색 결과 오염

### 원인

`wiki_dir.rglob("*.md")`가 `log.md` (변경 로그)와 `index.md` (목차)를 포함해 인덱싱. 이 파일들은 투자 원칙과 무관하지만 BM25 점수가 높게 산출되어 유용한 원칙 파일을 밀어냈다.

### 수정

```python
EXCLUDE_FILES = {"log.md", "index.md"}

for f in md_files:
    if f.name in EXCLUDE_FILES:
        print(f"[RAG] 제외: {f.name}")
        continue
    # ... 나머지 인덱싱 로직
```

---

## 문제 2: 핵심 원칙 파일 우선순위 부족

### 원인

BM25는 모든 파일을 동등하게 취급하므로 단순한 파일이 핵심 원칙 파일보다 높은 점수를 얻을 수 있었다.

### 수정 — rag_priority: high 부스트

위키 파일 YAML frontmatter에 `rag_priority: high`를 추가하면 해당 파일의 청크를 BM25 코퍼스에 2배 반복 삽입해 검색 우선순위를 높인다.

```python
RAG_PRIORITY_HIGH_BOOST = 2

fm_match = re.match(r"^---\n(.*?)\n---", text, re.DOTALL)
if fm_match and "rag_priority: high" in fm_match.group(1):
    boost = RAG_PRIORITY_HIGH_BOOST
for chunk in _split(text):
    for _ in range(boost):
        docs.append(chunk)
        metas.append({"source": f.name})
```
