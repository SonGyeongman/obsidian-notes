# 함수 참조

> inject.js, background.js, rag_server.py의 모든 함수를 파일별로 정리한다.

---

## inject.js

### URL 매칭 / 추출

#### `matchRule(url: string): string | null`
`INTERCEPT_RULES`를 순회하여 URL에 매칭되는 eventType을 반환.
매칭 없으면 `null`.

#### `extractUrl(input): string`
fetch의 `input` 인자(string / URL / Request)에서 URL 문자열을 추출.

#### `extractTickerFromUrl(url: string): string | null`
URL에서 종목 코드를 추출. 우선순위:
1. 쿼리 파라미터 (`productCode` → `code` → `ticker` → `symbol`)
2. 경로 세그먼트에서 `[A-Z0-9]{5,15}` 패턴 탐색

---

### 페이로드 정규화

#### `normalizeRankData(raw): RankItem[]`
인기 순위 응답 → `[{symbol, name, marketCode}]` 배열.

- 입력: `{ result: { data: [{symbol, name, market:{code}}] } }`
- 출력: `[{symbol, name, marketCode}]` (symbol 없으면 제거)

#### `normalizeRankingDataUS(raw): SupplyItem[]`
해외주식 거래대금 랭킹 응답 정규화.

- 입력: `{ result: { products: [{rank, productCode, name, price:{close}, extraInfo:{tossSecuritiesBuy, tossSecuritiesSell}}] } }`
- 출력: `[{rank, productCode, name, price, buy, sell}]`

#### `normalizeChartHistory(raw, meta): {ticker, prices} | null`
차트 API 응답 → `{ticker, prices: number[]}` (시간 오름차순 정렬).

1. ticker: `raw.result.code` 우선, 실패하면 URL 파싱
2. candles: `result.candles` → `result.data` → `candles` → `data` → 최상위 배열 폴백
3. 종가: `close → closePrice → c → endPrice → last`
4. 시간: `dt → time → timestamp → date → t` (ISO 8601 문자열 또는 Unix ms)
5. 종가 0개이거나 ticker 추출 실패 시 `null` 반환 → postMessage 스킵

#### `normalizePayload(eventType, raw, meta): any | null`
이벤트 타입에 따라 위 함수들을 디스패치.
미등록 타입은 raw 그대로 반환. CHART_HISTORY 결과만 null이 될 수 있음.

### 메시지 전송

#### `postIntercepted(eventType, payload, meta)`
`window.postMessage`로 content.js에 데이터를 전달.

```javascript
window.postMessage({
  namespace: "TOSS_INTERCEPTOR",
  eventType,
  payload,
  meta: { url, method, timestamp: Date.now() }
}, window.location.origin)
```

---

### 인터셉터

#### `window.fetch` (monkey-patch)
모든 fetch 요청을 가로채어:
1. `_originalFetch`로 실제 요청 전달
2. `response.clone().json()`으로 응답 복사 (원본 훼손 없음)
3. URL이 INTERCEPT_RULES에 매칭되면 정규화 후 `postIntercepted` 호출
4. 원본 response를 페이지에 그대로 반환

#### `XMLHttpRequest.prototype.open` (monkey-patch)
`this._tossInterceptMeta = {method, url}` 저장.

#### `XMLHttpRequest.prototype.send` (monkey-patch)
`load` 이벤트 리스너 추가: responseText를 JSON 파싱 후 `postIntercepted` 호출.

### 개인 데이터 폴링

#### `parseSectionData(raw): object | null`
섹션 data 필드가 string이면 JSON.parse, 이미 object이면 그대로 반환.

#### `buildHoldings(sectionsResult): Holding[]`
`result.sections[type=="SORTED_OVERVIEW"].data.products[].items[]`를 파싱해 보유 주식 배열 생성.
- ticker: `stockSymbol` 우선 → `stockCode`
- qty 0 이하이면 제외
- `profitLossRate`는 소수 → ×100으로 %로 변환

#### `calcDailyPnL(sectionsResult): number | null`
보유 주식 전체의 `dailyProfitLossAmount.usd` 합계 계산.

#### `pollPersonalData(): Promise<void>`
`Promise.allSettled`로 3개 API를 동시 호출:
1. `GET /api/v3/my-assets/summaries/markets/all/overview` → 총 자산
2. `GET /api/v1/dashboard/common/cached-orderable-amount` → 주문 가능 금액
3. `POST /api/v2/dashboard/asset/sections/all` → 보유 주식

결과를 조합해 `TOSS_ASSET_SUMMARY`와 `TOSS_PORTFOLIO` 이벤트로 전송.

**실행 타이밍**: 페이지 로드 5초 후 최초 → 이후 60초 간격.

## background.js

### 유틸리티

#### `getSettings(keys: string[]): Promise<object>`
`chrome.storage.local.get`을 Promise로 래핑.

#### `sleep(ms: number): Promise<void>`
`setTimeout` 기반 딜레이.

#### `formatDatetime(ts?: number): {date, time, fileStamp, iso}`
타임스탬프를 날짜 문자열로 포맷팅.
- `date`: `YYYY-MM-DD`
- `time`: `HH:mm`
- `fileStamp`: `YYYYMMDD_HHmm` (Obsidian 파일명용)
- `iso`: ISO 8601 문자열

#### `sentimentColor(sentiment: string): number`
여론 문자열 → Discord Embed 색상 정수.
- 긍정: `0x57f287` (초록)
- 부정: `0xed4245` (빨강)
- 관망: `0x95a5a6` (회색)

#### `getStockState(ticker: string): StockState`
`stockState` Map에서 조회. 없으면 초기값으로 생성 후 반환.

### 지표 계산 (순수 함수)

#### `calcMA(prices: number[], period: number): number | null`
단순 이동평균 (SMA). `prices.length < period`이면 null.

#### `calcRSI(prices: number[], period: number): number | null`
RSI — Wilder's Smoothed Moving Average. 최소 `period + 1`개 필요.
avgGain/avgLoss 초기값을 seed (첫 period개)의 단순 평균으로 설정.

#### `calcEMA(prices: number[], period: number): number | null`
지수이동평균 (EMA). k = 2/(period+1).

#### `calcMACD(prices: number[]): MACDResult | null`
MACD (12, 26, 9). 최소 34개 필요.
1. EMA12, EMA26 동시 계산
2. MACD선 배열 생성
3. 시그널선 = EMA9 of MACD선
4. 히스토그램 = MACD - 시그널

#### `calcBollingerBands(prices: number[]): BBResult | null`
볼린저밴드 (20일, 2σ). 최소 20개 필요.
pctB = (현재가 - 하단) / (상단 - 하단).

#### `recalcIndicators(state: StockState): void`
state.prices 기준으로 모든 지표(MA5/20/60/120, RSI14, RSI2, MACD, BB)를 일괄 재계산해 state에 저장.

---

### 매매 신호 감지

#### `evaluateSignal(ticker: string, state: StockState): void`
신호 조건 체크:
1. `_botEnabled === false` → 즉시 리턴
2. `prices.length < MA_LONG` → 데이터 부족 리턴
3. 쿨다운 5분 미경과 → 리턴
4. `_pendingSignalTickers.has(ticker)` → AI 파이프라인 중복 방지
5. **골든크로스**: `prevMa5 < prevMa20 && ma5 >= ma20`
6. **RSI 과매도**: `rsi <= 30`
7. 조건 충족 시 `runAgentPipeline` 비동기 실행 (가격 틱 루프 블로킹 없음)

#### `emitBuySignal(ticker, detail): void`
BUY 신호 확정 시:
1. `chrome.storage.local.set({ signal_{ticker}: signal })` 저장
2. `sendDiscordAlert` fire-and-forget
3. `saveToObsidian` fire-and-forget

---

### Discord / Obsidian 연동

#### `sendDiscordAlert(ticker, signal, state): Promise<void>`
Discord Webhook Embed 전송.
- 설정에서 `discordWebhookUrl` 조회 → 없으면 경고 후 리턴
- Embed 필드: 신호유형, 현재가, MA5/20, RSI, AI결정, 투입비중, 기대수익률, 목표가, 손절가, AI근거, 커뮤니티여론

#### `saveToObsidian(ticker, signal, state): Promise<void>`
Obsidian Local REST API (`PUT /vault/Trading_Logs/{filename}.md`)로 마크다운 저장.
파일명: `{ticker}_{YYYYMMDD_HHmm}.md`

#### `buildMarkdown({ticker, signal, state, dt, sentiment, price}): string`
Obsidian 저장용 마크다운 문서 생성.
구조: YAML Frontmatter → 지표 테이블 → AI 퀀트 판단 → 커뮤니티 여론 → 메모 공간.

### AI 파이프라인

#### `searchWikiKnowledge(ticker, name, reason, indicators): Promise<string>`
RAG 서버 `POST /api/rag/search`에 쿼리 전송.
- 쿼리 문장: "종목명은 {name}이고, {신호 설명} 상태야. 현재가 ${price}. ..."
- top_k = 3
- 서버 미기동 시 빈 문자열 반환 (파이프라인 계속 진행)

#### `decideTradeWithQwen(signalDetail, wikiContext): Promise<TradeDecision>`
Ollama `POST /api/generate`로 Qwen2.5:14b에 매매 판단 요청.
- 시스템 프롬프트: `OLLAMA_TRADER_SYSTEM_PROMPT`
- 프롬프트에 포함: 현재가, MA5/20/60/120, 정배열 판정, MACD 해석, %b 해석, RSI 단계, 수급, 외부펀더멘털(현재 null), 가용자본 $10,000, 위키 RAG 결과

**가드레일 체크 (순서대로)**:
1. 목표가 > 현재가 확인 (아니면 PASS 강제)
2. 손절가 < 현재가 확인 (아니면 PASS 강제)
3. 손절폭 ≤ 5% (초과 시 PASS 강제)
4. 손익비 ≥ 1.5배 (미달 시 PASS 강제)
5. 순수익률 ≥ 1.5% (미달 시 PASS 강제)

**AI 환각 보정**:
- allocation_percent > 1.0이면 ÷ 100 정규화

파싱 실패 시 `SAFE_PASS` 반환.

#### `analyzeSentimentWithQwen(text, ticker): Promise<SentimentResult | null>`
커뮤니티 게시글 텍스트를 Qwen에 전달해 여론 분석.
- 시스템 프롬프트: `OLLAMA_SYSTEM_PROMPT` (JSON 형식 강제)
- 결과를 `state.sentiment`에 저장 후 반환

#### `runAgentPipeline(ticker, detail): Promise<void>`
신호 감지 후 전체 AI 파이프라인 실행:
1. `searchWikiKnowledge` — RAG 위키 검색
2. `decideTradeWithQwen` — AI 매매 판단
3. `chrome.storage.local.set({ agentLog })` — 판단 이력 저장 (최근 20개)
4. PASS → 로그 출력 후 종료
5. BUY/SELL → `emitBuySignal` 호출

### Service Worker 지속성

#### `restoreStockState(): Promise<void>`
SW 재기동 시 `chrome.storage.local._stockPrices`에서 prices 배열을 복원하고 `recalcIndicators`로 지표 재계산.

#### `scheduleStatePersist(): void`
3초 디바운스로 모든 종목의 prices를 `chrome.storage.local._stockPrices`에 스냅샷 저장.
가격 업데이트 직후 호출되어 SW 종료에 대비.

### SSE 연결

#### `streamSSE(url, signal): Promise<void>`
fetch + ReadableStream으로 SSE 텍스트 파싱.
- `event:`, `data:`, `id:` 필드 라인 파싱
- 빈 줄에서 이벤트 발송 (`handleSSEEvent`)
- AbortSignal로 외부 중단 가능

#### `handleSSEEvent({eventType, data}): void`
SSE 이벤트 처리:
- `connection-close` → 즉시 재연결
- `share-holdings` / `purchase-price-refresh` → 즉시 `pollTrackedPrices()`

#### `connectNotificationSSE(): Promise<void>`
SSE 알림 채널 연결. 이미 연결 중이면 즉시 리턴.
종료/실패 시 30초 후 자동 재연결.

#### `disconnectNotificationSSE(): void`
`sseController.abort()`로 SSE 연결 강제 해제.

#### `maintainSSEConnection(): void`
keepalive 알람(24초)에서 호출. SSE 미연결이면 재연결 시도.

### 가격 폴링

#### `pollTrackedPrices(): Promise<void>`
`trackedTickers` 전체를 쉼표로 이어붙여 REST API 1회 호출.
응답을 `handleQuotesData(items)`로 전달.
첫 응답 시 필드 구조 로그 (디버깅용, `_logged` 플래그).

#### `startTrackingTicker(ticker: string): void`
종목을 `trackedTickers`에 추가.
신규 종목이고 prices가 200개 미만이면 `fetchHistoricalChartData` 트리거.

### 차트 시드 (Cold-Start 해결)

#### `fetchHistoricalChartData(ticker, targetCount=200): Promise<void>`
1분봉 API를 페이지네이션하여 `targetCount`개 이상 캔들 수집.
- 각 페이지: `GET /api/v1/c-chart/us-s/{ticker}/min:1?count=397[&endTime=...]`
- `result.nextDateTime`으로 다음 페이지 이동
- 페이지 간 400ms 딜레이
- 수집 완료 후 `handleChartHistory()`로 stockState에 병합

### 데이터 핸들러

#### `handleRankData(payload, meta): void`
인기 순위 100 처리:
- 회사명 저장 (`state.name`)
- 상위 10개 → `startTrackingTicker`
- 나머지 90개 → `getStockState` 사전 등록만

#### `handleQuotesData(payload, meta): void`
실시간 시세 처리:
1. payload를 quotes 배열로 정규화 (4가지 형태 지원)
2. 각 quote에서 ticker/price 추출
3. `state.prevMa5/prevMa20` 갱신 → `state.prices` 업데이트 → `recalcIndicators` → `evaluateSignal`
4. `scheduleStatePersist`

#### `handleChartHistory(payload): void`
과거 캔들 시드 처리:
- 기존 prices가 seed보다 많으면 스킵 (실시간 데이터 우선)
- 그렇지 않으면 `[...seed, ...기존].slice(-MAX_PRICE_HIST)` 병합
- `prevMa5/prevMa20` null 리셋 (seed 기반 오탐 방지)

#### `handleRankingDataUS(payload, meta): void`
거래대금 랭킹 수급 처리:
- 100개 종목 `state.supplyData` 갱신
- 매수/매도 비율(ratio) 계산: buy/sell (sell=0이면 null)
- ratio ≥ 2.0인 종목은 수급 강세 감지 → `startTrackingTicker`
- 상위 5개 요약 로그

#### `handleCommunityData(payload, meta): Promise<void>`
커뮤니티 게시글 처리:
- 최대 10개 게시글 텍스트 조합
- `analyzeSentimentWithQwen` 호출

#### `handleAssetSummary(payload): void`
`chrome.storage.local.set({ assetSummary: payload })`

#### `handlePortfolio(payload): void`
`chrome.storage.local.set({ portfolio: payload })`

## rag_server.py

### 텍스트 처리

#### `_split(text: str) -> list[str]`
단락(`\n{2,}`)으로 분리 후 CHUNK_SIZE(400자) 기준으로 청킹.
CHUNK_OVERLAP(60자) 겹침으로 문맥 연속성 유지.
20자 미만 청크는 제거.

#### `_tokenize(text: str) -> list[str]`
한국어/영어 혼합 토크나이저. `[A-Za-z0-9]+|[가-힣]+` 패턴으로 소문자 토큰 추출.

---

### 인덱스

#### `init_index() -> None`
서버 기동 시 1회 실행:
1. `WIKI_PATH.rglob("*.md")`로 전체 마크다운 파일 탐색
2. `EXCLUDE_FILES`에 해당하는 파일 건너뜀
3. YAML frontmatter에서 `rag_priority: high` 감지 시 청크를 `RAG_PRIORITY_HIGH_BOOST`(=2)배 반복 삽입
4. `BM25Okapi(tokenized)`로 인덱스 빌드
5. 전역 `_chunks`, `_metas`, `_bm25` 업데이트

---

### API 엔드포인트

#### `POST /api/rag/search`
요청: `{query: string, top_k: int}`

1. `_tokenize(query)`로 쿼리 토큰화
2. BM25 점수 계산 후 상위 top_k 인덱스 추출
3. score > 0인 청크만 포함 (무관 문서 제거)
4. `"[파일명]\n{청크내용}"` 형태로 `"---"` 구분 조합

응답: `{context: string, chunks_found: int}`

#### `GET /health`
응답: `{ok: true, vector_db_ready: bool, chunks: int}`
